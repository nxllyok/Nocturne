# NOCTURNE — The Midnight Archive

**NOCTURNE** — веб-блог, разработанный на Python с использованием Flask. Проект сочетает функциональность современной блог-платформы.

Пользователи могут регистрироваться, входить в свои аккаунты, читать публикации, а также создавать, редактировать и удалять собственные записи.

---

## 1. Основные возможности

- **Регистрация пользователей** — создание нового аккаунта.
- **Авторизация** — вход в систему с использованием электронной почты и пароля.
- **Безопасное хранение паролей** — хеширование с помощью Werkzeug.
- **Выход из аккаунта** — безопасное завершение пользовательской сессии.
- **Создание публикаций** — добавление новых записей в блог.
- **Просмотр публикаций** — отдельная страница для каждой записи.
- **Редактирование публикаций** — изменение собственных записей.
- **Удаление публикаций** — удаление собственных записей.
- **Проверка пользовательского ввода** — валидация форм и обязательных полей.
- **Пагинация** — разделение списка публикаций на страницы.
- **Адаптивный дизайн** — удобное отображение сайта на разных размерах экранов.
- **Многоязычный интерфейс** — поддержка предусмотренных в проекте языков.

- `__init__.py` — создание и настройка приложения Flask.

## 3. Установка и запуск

### Шаг 1. Установка Python

Для запуска проекта необходим установленный Python.

Проверить его наличие можно командой:

```powershell
python --version
```

### Шаг 2. Открытие папки проекта

Откройте терминал и перейдите в директорию проекта:

```powershell
cd D:\Programs\Synergy\Homework\Nocturne
```

### Шаг 3. Установка зависимостей

Установите все необходимые библиотеки:

```powershell
python -m pip install -r requirements.txt
```

### Шаг 4. Настройка переменных окружения

В корневой папке проекта должен находиться файл `.env`.

В нём необходимо указать секретный ключ приложения:

```text
SECRET_KEY=your-long-random-secret-key
```

Для реального развёртывания необходимо использовать собственный случайный секретный ключ и не публиковать файл `.env`.

### Шаг 5. Подготовка базы данных

Если миграции ещё не были созданы, сначала выполните:

```powershell
python -m flask --app run.py db init
```

Затем создайте миграцию:

```powershell
python -m flask --app run.py db migrate -m "Initial migration"
```

Примените миграцию:

```powershell
python -m flask --app run.py db upgrade
```

Если папка `migrations` уже существует, повторно выполнять команду `db init` не нужно.

### Шаг 6. Запуск приложения

Запустите веб-приложение:

```powershell
python run.py
```

После успешного запуска откройте браузер и перейдите по адресу:

http://127.0.0.1:5000

## 4. База данных

Для хранения данных используется SQLite.

В проекте предусмотрены две основные модели:

### User

Модель пользователя содержит:

- ID пользователя;
- имя пользователя;
- адрес электронной почты;
- хеш пароля;
- дату создания аккаунта.

### Post

Модель публикации содержит:

- ID публикации;
- заголовок;
- содержание;
- дату создания;
- дату последнего изменения;
- ID автора публикации.

Связь между моделями позволяет одному пользователю создавать несколько публикаций.

Flask-SQLAlchemy используется для взаимодействия с базой данных, а Flask-Migrate — для управления изменениями её структуры.

## 5. Безопасность

В приложении предусмотрены следующие механизмы безопасности:

1. Пароли сохраняются в виде хешей с использованием Werkzeug.
2. Flask-Login управляет авторизацией пользователей.
3. Flask-WTF обеспечивает CSRF-защиту форм.
4. WTForms проверяет корректность введённых данных.
5. Только авторизованные пользователи могут управлять публикациями.
6. Пользователь может редактировать и удалять только собственные записи.
7. Секретный ключ приложения хранится в переменной окружения.

## 6. Архитектура приложения

Проект использует структуру, разделяющую разные части приложения.

- **Models** отвечают за структуру и хранение данных.
- **Routes** обрабатывают HTTP-запросы и определяют поведение приложения.
- **Forms** отвечают за получение и проверку пользовательского ввода.
- **Templates** отвечают за отображение страниц.
- **Static** содержит CSS-файлы и другие статические ресурсы.
- **Config** содержит настройки приложения.

Такое разделение делает проект более понятным, удобным для поддержки и дальнейшего расширения.
